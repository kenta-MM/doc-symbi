# AIによる文書の作成・修正

ローカルサーバーを起動し、設定でCodexを選択してAIチャットに接続します。

- **新規作成**：「Azureフォルダ以下にAzure Policyという文書を作って」などと依頼し、作成案の保存先と「内容を確認」から本文を確認して「文書を作成」を押します。指定したフォルダーに保存する下書きが開きます。指定しなかった場合は選択中のフォルダーを使います。
- **既存文書の修正**：対象文書を開いて「説明を短くして」「手順を追加して」などと依頼します。修正案を確認して「変更を適用」を押すと編集モードになります。
- **保存**：適用時点では未保存です。本文を確認して通常の「保存」で保存します。本文の修正はエディターの取り消し・やり直しを利用できます。

依頼後に文書や保存先が変わった場合、古い案は適用できません。最新の状態でもう一度依頼してください。未保存の文書を開いたまま新規作成する場合は、先に保存してください。

AIには利用可能なフォルダーの相対パス一覧も渡します。作成先は既存のフォルダーのみ指定できます。同名のフォルダーが複数ある場合は「部門A/Azure」のようにパスを指定してください。存在しないフォルダーや一意に特定できない指定については、AIに確認を求めるよう指示しています。適用時にも利用可能なパスか検証し、別の場所への代替保存はしません。

## 操作の範囲

新規作成では見出し、段落、コード、リスト、表を生成できます。修正は開いている文書のタイトルと、トップレベルのブロックの置き換え・追加・削除に対応します。対象外のブロックは保持されます。置き換えるブロックの本文書式や子要素は新しい内容になります。画像やクイズの新規生成は対象外です。

## 実装

Codex App Serverの`turn/start.outputSchema`で`message`と`action`を受け取ります。サーバーとブラウザで形式を検証し、応答が正常に完了した場合だけ適用ボタンを表示します。任意のファイルパスや実行コードを操作として受け付けません。

`ai-document-actions.ts`が明示的な作成・修正操作を検証して文書モデルを生成し、`apply-ai-document.ts`が文書セッションの世代を照合して適用します。既存本文はエディターのトランザクション経由で更新し、保存は既存のリポジトリ処理と競合検知を使用します。

既存のCodexログインを使用します。Claude連携は従来どおり準備中です。
