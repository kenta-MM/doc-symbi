# 文書専用の画像・説明ファイル

## 決定した仕様

同じ画像を文書間で使い回すことは前提にしない。画像と説明情報は、貼り付け先の文書と画像ブロックが所有する。共有素材庫や、説明を複数文書に一括反映する機能は設けない。同じ画像を別の文書へ貼り付けても独立したコピーとして扱う。

フォルダー保存時は、文書本体・画像の説明JSON・画像ファイルを分離する。

```text
保存フォルダー/
├─ 文書名--識別子.docsymbi.json
└─ _docsymbi-assets/
   └─ 文書ID/
      └─ 画像ブロックID/
         ├─ 内容識別子.json
         └─ 内容識別子.png  （または jpg / webp / svg）
```

文書本体の画像ブロックは `id`、`metadata`、`assetRef`（説明JSONへの相対パス）、任意の `displaySize` を保持する。`assetRef` の基準は文書ファイルのあるフォルダー。

説明JSONは `format: "docsymbi-image"`、`schemaVersion: 1`、`documentId`、`blockId`、`caption`、`alt`、`semantics`、`file` を持つ。`file` は画像ID、元ファイル名、MIME、サイズ、寸法、`path`。`path` の基準は説明JSONのあるフォルダーで、画像バイト列はJSONに入れない。

キャプション・代替テキスト・目的・要約・構成要素・関係・読み順・前提・出典は、すべてこの文書専用の説明JSONに保存する。表示サイズは文書本体に保存する。

## ファイル形式と互換性

- 画像を含むフォルダー保存文書は `schemaVersion: 5`。`bodySchemaVersion` に編集用モデルの版（1〜4）を記録する。
- v1〜v4の埋め込み文書はそのまま読める。閲覧だけでは書き換えず、画像を含む文書の次回保存時に分離形式へ変換する。
- 編集画面では説明・画像を読み込んだモデルを使用するため、既存の画像編集、Undo/Redo、AI向け説明データは維持する。画像を多数持つ文書の表示・編集には、その分のメモリーが必要になる。
- 画像を含まない文書は従来の本文形式で保存する。旧ブラウザ内保存も従来形式のまま読み書きでき、フォルダーへ移す際に分離する。

## 容量

本文・書式・説明情報・metadataの合計はUTF-8で10 MiBまで。画像本体はこの合計から除外する。画像1枚あたり・画像合計のバイト容量にはアプリ独自の上限を設けない。実際に扱える容量はブラウザのメモリーと保存領域に依存する。本文100万文字、要素1万、リスト深さ32、画像の縦横各20,000ピクセルの上限は維持する。

「文書を取り出す」は持ち運び用の自己完結JSONであり、例外として画像をBase64で同梱する。上限は画像込み256 MiB。取り込み後の通常のフォルダー保存では再び分離する。保存用v5の文書本体だけをファイル読み込みで渡した場合は、画像が付属していないため操作方法を案内する。

## 保存・移動・削除

- 説明と画像を先に書いて読み戻し確認し、その後に文書本体を更新する。文書本体の更新に失敗した場合は新規に作った素材ファイルだけを片付け、以前の文書と素材を残す。
- 内容識別子は画像データと説明情報から作る。文書・画像ブロックごとのフォルダー内でのみ利用し、文書間で共有・重複排除しない。本文だけを更新した場合、同じ素材ファイルを毎回書き直さない。
- 保存成功後、以前参照していた不要な素材を整理する。強制終了で生じた未参照ファイルは自動で全探索削除せず、文書削除時にその文書専用フォルダーと一緒に削除する。
- アプリ内の文書移動では関連ファイルもコピー・検証してから元を削除する。文書名変更では文書IDを変えないので素材の所有関係を維持する。フォルダー名変更も素材ごと移す。
- 文書削除では、その文書専用素材フォルダーを削除する。他文書の素材は対象にしない。素材整理だけ失敗した場合、成功した文書保存・削除を失敗扱いに戻さず警告を記録する。
- `_docsymbi-assets` はアプリ管理用の予約名。文書一覧・フォルダーツリーの対象から除外する。
- OS上で手動移動・バックアップする場合は、文書JSONと対応する `_docsymbi-assets/文書ID` を同じ相対配置で扱う。単体で渡す場合は「文書を取り出す」を使う。

## 参照と競合の検査

絶対パス、`..`、別文書の素材パスは受け付けない。説明JSONにある所有文書ID・画像ブロックID、画像形式、バイト数などを検証する。関連ファイルが欠落・破損している場合は、パス付きのエラーを表示し、空画像への置換や欠落したままの上書きはしない。

保存競合の比較には文書本体だけでなく説明JSONと画像バイト列も含める。説明JSONを外部編集した場合も、古い画面からの上書きを拒否する。同一originの読取・書込はWeb Locksで調整するが、OS上の別アプリとの完全な排他は行えない。
