# Feature Specification: DocSymbi 構造化ドキュメントエディタ初期MVP

**Feature Branch**: 未作成（作業ブランチ: `main`）

**Created**: 2026-10-25

**Status**: Draft

**Input**: User description: 人間とAIのための構造化ドキュメントエディタDocSymbiの初期MVP。
新規作成・表示・編集・名前変更・削除、段落・見出し・箇条書き・番号付きリスト・コードブロック、
マークアップ不要のビジュアル編集、構造と意味の保持、機械可読形式のローカル保存と再読み込み、
見出しによる移動、Undo／Redo、オフライン閲覧・編集を実現する。
単一モデルで人間の使いやすさとAIが理解できる構造化データを両立することを実証し、
機能の網羅性よりモデルの正確性と基本編集体験の完成度を優先する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 文書を書き、保存して再び開く (Priority: P1)

利用者は空の文書を作り、マークアップを記述せずに文章や構造を編集する。
ローカルに保存した文書をアプリ終了後に開き直しても、同じ内容と構造で作業を続けられる。

**Why this priority**: 編集から永続化までの一連の操作が、単一モデルの正確性と製品価値を示す。

**Independent Test**: 空の環境で全5種類のブロックを含む文書を作成・保存し、終了後に
開き直して本文、順序、見出しレベル、リスト階層、コードの空白が一致することを確認する。

**Acceptance Scenarios**:

1. **Given** 文書がない状態、**When** 新規作成を選ぶ、**Then** 識別可能な仮の名前を持つ
   空の文書が開き、そのまま本文を入力できる。
2. **Given** 編集中の文書、**When** 画面上の操作で段落、見出し、箇条書き、番号付きリスト、
   コードブロックを追加する、**Then** マークアップを入力せず、それぞれの種類で編集できる。
3. **Given** 複数のブロックがある文書、**When** 本文修正、ブロックの挿入・削除・移動、
   段落と見出しの相互変換、見出しレベル変更、リスト項目の追加・削除・字下げを行う、
   **Then** 意図した部分だけが変化し、他の内容と関係は維持される。
4. **Given** 日本語、入れ子リスト、複数レベルの見出し、改行と空白を含むコードがある文書、
   **When** 保存完了後にアプリを終了して再度開く、**Then** 内容、順序、種類、階層と
   メタデータが保存時と意味的に一致する。
5. **Given** 未保存の変更がある文書、**When** 保存が失敗する、**Then** 保存済みとは表示せず、
   原因と再試行方法を示し、現在の編集内容と最後に正常保存されたデータを保持する。
6. **Given** 空の文書、**When** 保存して再度開く、**Then** 空のまま正常に開き、編集を続けられる。

---

### User Story 2 - ローカルの文書を管理する (Priority: P1)

利用者は保存済み文書を一覧から選び、名前を変更し、不要な文書を削除する。
文書の名前や操作対象を確認しながら、複数の文書を安全に管理できる。

**Why this priority**: 保存した文書を継続利用するための基本操作である。

**Independent Test**: 用意した2件の文書に対し、一覧表示、選択、名前変更、削除のキャンセルと
確定を実行し、再起動後にも結果が保たれ、他の文書が変化していないことを確認する。

**Acceptance Scenarios**:

1. **Given** 保存済み文書が複数ある、**When** 一覧から文書を選ぶ、**Then** 対応する名前と
   本文が表示され、同名の文書でも別の文書として識別できる。
2. **Given** 文書が開かれている、**When** 名前を変更して保存する、**Then** 一覧と文書内の名前が
   更新され、再起動後も本文と文書の識別情報を保持したまま新しい名前で開ける。
3. **Given** 名前変更中、**When** 空文字または空白だけの名前を確定する、**Then** 理由を示して
   確定を拒否し、元の名前を保持する。
4. **Given** 削除対象を選んだ状態、**When** 削除を要求する、**Then** 対象名を示す確認があり、
   キャンセルすれば変更されず、確定すれば一覧から消えて再起動後も復活しない。
5. **Given** 未保存の変更がある、**When** 別文書への切り替えや文書を閉じる操作をする、
   **Then** 保存を完了するか、保存・破棄・移動中止の選択を求め、黙って変更を失わない。

---

### User Story 3 - 見出しを使って目的の箇所へ移動する (Priority: P2)

利用者は見出しの階層を一覧で把握し、目的の節へ移動して閲覧・編集する。

**Why this priority**: 文書が長くなっても構造を手がかりに移動できることを示す。

**Independent Test**: 見出しの重複名とレベルの飛びを含む文書を開き、アウトラインの順序・階層と
選択先を確認する。見出しの変更・削除に合わせて表示が更新されることも確認する。

**Acceptance Scenarios**:

1. **Given** 異なるレベルの見出しがある、**When** 文書を開く、**Then** 本文の順序とレベルに
   対応するアウトラインが表示される。
2. **Given** 同名の見出しが複数ある、**When** アウトラインの一つを選ぶ、**Then** 対応する
   見出しが画面内に表示され、同名の別の箇所へ誤って移動しない。
3. **Given** アウトラインを表示中、**When** 見出しの本文・レベル・順序を変えるか削除する、
   **Then** 再読み込みせずアウトラインが更新される。
4. **Given** 見出しがない、**When** 文書を開く、**Then** 見出しがないことが分かり、通常の
   本文編集は妨げられない。

---

### User Story 4 - 編集を取り消し、やり直す (Priority: P2)

利用者は誤った本文編集や構造変更を取り消し、必要ならやり直して、安心して編集する。

**Why this priority**: 基本編集体験を完成させ、構造変更時の誤操作から回復できるようにする。

**Independent Test**: 用意した文書で本文、ブロック種類、順序、リスト階層を変更し、UndoとRedoで
変更前後の意味的な状態に戻ることを、他の機能の操作なしで確認する。

**Acceptance Scenarios**:

1. **Given** 本文または構造を変更した直後、**When** Undoを実行する、**Then** 対象の操作前の
   内容・順序・階層に戻る。**When** Redoを実行する、**Then** 同じ変更後の状態に戻る。
2. **Given** Undoした直後、**When** 新しい編集を行う、**Then** 以前のRedo候補は無効になる。
3. **Given** Undo／Redoの対象がない、**When** 操作を試みる、**Then** 利用不能であることが分かり、
   文書は変更されない。
4. **Given** 同じ文書を開いたまま保存した、**When** Undoを実行する、**Then** 保存前の本文編集も
   取り消せ、その結果は未保存の変更として扱われる。
5. **Given** 文書Aに編集履歴がある、**When** 文書Bを開いてUndoする、**Then** Aの変更はBに
   適用されない。

---

### User Story 5 - オフラインで使い、構造化データを持ち出す (Priority: P1)

利用者は利用準備済みの環境でネットワークを切断しても作業できる。
自身の文書を機械可読なデータとして取り出し、別のローカル環境で同じ文書を復元できる。

**Why this priority**: データ所有権と、表示に依存しないAI向けの情報保持を実証する。

**Independent Test**: ネットワークを切断してアプリを再起動し、基本操作を実行する。
取り出したデータと形式説明だけで文書の構造を検証し、空のローカル環境へ復元する。

**Acceptance Scenarios**:

1. **Given** 利用準備が完了した環境、**When** ネットワークを切断して起動する、**Then**
   アカウント認証なしで新規作成、表示、編集、名前変更、削除、保存、再読み込み、
   アウトライン移動、Undo／Redoが利用できる。
2. **Given** 全対応ブロックを含む保存済み文書、**When** 正規形式のデータを取り出す、**Then**
   名前、ブロック種別、本文、順序、見出しレベル、リストの親子関係、識別情報、形式の版を、
   画面や装飾を解析せず、形式説明に沿って機械的に判別できる。
3. **Given** 取り出した正規形式の文書、**When** 文書のない別のローカル環境へ読み込む、
   **Then** 内容・構造・メタデータが一致し、通常どおり編集できる。
4. **Given** 破損データ、未対応の版・ブロック種別、または既存文書と識別情報が衝突するデータ、
   **When** 読み込みを試みる、**Then** 理由を示して拒否し、入力データと既存文書を変更しない。

### Edge Cases

- 空文書、同名文書、空の見出しを許容する。空の見出しはアウトラインで仮表示し、本文は改変しない。
- 見出しレベルの飛びを許容する。親は直前のより浅いレベルの見出しとし、存在しなければ
  最上位として扱う。存在しない中間見出しを本文に追加しない。
- 箇条書きと番号付きリストは混在・入れ子を許容する。字下げ先の親項目がない操作は無効とし、
  元の内容を保持する。番号付きリストは各階層で1から順に表示する。
- コードの改行、字下げ、連続空白、日本語・絵文字は保存と再読み込みで保持する。
  コードは内容として表示し、実行しない。
- 日本語の変換確定中に文字が二重挿入・欠落しない。確定済み入力はUndo／Redoの対象になる。
- 貼り付けはプレーンテキストを基本とし、外部の装飾や複雑な構造の再現は保証しない。
  コードブロック内では貼り付けた改行・空白を保持する。
- 保存領域不足や書き込み不可のときは保存失敗を表示し、再試行可能な編集状態を保持する。
  保存途中の失敗で最後の正常保存データを壊さない。
- 想定外の終了では最後に保存完了した状態を復元できる。保存未完了の編集の復旧は保証しない。
- 同一文書への複数画面・複数プロセスからの同時編集は対象外。古い状態からの保存が検出された
  場合は上書きを拒否し、編集中の内容を保持したまま競合を知らせる。自動マージは行わない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は文書を新規作成し、ローカルの文書一覧から選択して表示・編集できなければ
  ならない。空文書も有効とする。（US1-1, US1-6, US2-1）
- **FR-002**: 利用者は名前変更と確認付き削除を行えなければならない。空白だけの名前は拒否し、
  同名でも別文書を識別でき、管理操作の結果を再起動後も保持しなければならない。（US2-1〜4）
- **FR-003**: 段落、6段階の見出し、箇条書き、番号付きリスト、コードブロックを扱い、
  マークアップを入力せず画面上の操作で追加・編集できなければならない。（US1-2）
- **FR-004**: ブロックの挿入・削除・順序変更、段落と見出しの相互変換、見出しレベル変更、
  リスト項目の追加・削除・字下げ・字下げ解除ができなければならない。
  リストは少なくとも3階層の入れ子と種類の混在を扱わなければならない。（US1-3）
- **FR-005**: 単一の正規ドキュメントモデルで、人間向けの編集・表示と機械可読データを
  表現しなければならない。画面上の見た目を解釈し直さずに構造を取得できなければならない。
  （US1-4, US5-2）
- **FR-006**: 編集で明示的に変更した箇所以外の内容、ブロック種別、順序、階層、関係、
  識別情報とメタデータを保持しなければならない。保存・再読み込みでそれらが意味的に
  同等でなければならない。更新日時は実際の更新を反映してよい。（US1-3〜4, US5-3）
- **FR-007**: ローカルへの保存と再読み込みを提供し、利用者が保存を明示的に実行でき、
  未保存・保存中・保存済み・保存失敗を判別できなければならない。（US1-4〜5）
- **FR-008**: 保存失敗時は再試行方法を示し、編集中の内容と最後の正常保存状態を保持し、
  未保存の変更を伴う文書切り替え・終了では黙って変更を失ってはならない。（US1-5, US2-5）
- **FR-009**: 見出しの順序・階層を示すアウトラインを提供し、対応箇所への移動と編集後の
  更新を行わなければならない。同名・空の見出し、レベルの飛びでも対象を誤ってはならない。
  （US3-1〜4, Edge Cases）
- **FR-010**: 本文と構造の編集に対するUndo／Redoを、画面上の操作と一般的なキーボード操作で
  提供しなければならない。同じ文書を開いている間は少なくとも直近100編集操作を扱い、
  保存では履歴を消さず、Undo後の新しい編集ではRedo候補を破棄しなければならない。
  名前変更・文書削除・文書切り替えは本文の履歴に含めない。（US4-1〜5）
- **FR-011**: 利用準備後は、再起動を含め全MVP操作をネットワーク接続・アカウント・外部サービス
  なしで利用できなければならない。文書内容を外部送信してはならない。（US5-1）
- **FR-012**: 正規形式のデータを取り出して移動・復元でき、形式の版と意味を説明した文書を
  提供しなければならない。外部の文書形式への変換は必須ではない。（US5-2〜3）
- **FR-013**: 読み込み時に形式・版・構造の制約を検証し、破損や未対応の要素、識別情報の
  衝突を黙って補正・破棄・上書きしてはならない。拒否理由を表示し、元データと既存文書を
  保持しなければならない。（US5-4）
- **FR-014**: 保存時に他の画面などからの更新との競合を検出した場合、古い内容による
  無通知の上書きを防止し、現在の編集内容を保持しなければならない。（Edge Cases）
- **FR-015**: 日本語の入力・変換と確定、絵文字、コードの空白・改行を欠落なく扱い、
  コードを実行せず、プレーンテキストの貼り付けを提供しなければならない。（US1-4, Edge Cases）

### Key Entities *(include if feature involves data)*

- **ドキュメント**: 安定した識別情報、名前、順序を持つ本文、作成・更新日時、形式の版を持つ。
  名前変更後も同じ文書であり、同名の他の文書とは区別される。
- **ブロック**: 安定した識別情報、種類、内容、順序と種類に応じた属性を持つ意味的な単位。
  種類は段落、見出し、リスト、コードブロック。見出しにはレベルがある。
- **リスト項目**: リスト内の順序、本文、子リストとの親子関係を持つ。親リストが箇条書きか
  番号付きかを定める。表示する番号は文書の意味の唯一の表現ではない。
- **アウトライン項目**: 見出しに対応する表示名、レベル、移動先を持つ派生情報。
  独立した正規データではなく、本文から導かれる。
- **保存状態・編集履歴**: 保存の成否と未保存変更、Undo／Redoの対象を表す作業状態。
  本文の意味とは分離し、別の正規ドキュメントを形成しない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全対応ブロック、見出し6レベル、3階層の混在リスト、日本語、絵文字、コードの
  空白・改行、空文書を含む20件以上の検証文書で、編集・保存・再読み込みを各10回行い、
  意図しない内容・構造・識別情報・メタデータの損失が0件である。（FR-003〜008, FR-015）
- **SC-002**: 初めて利用する5人中4人以上が、口頭の操作補助なしで、名前付き文書の作成、
  見出し・段落・リスト・コードの挿入、保存、再読み込みを10分以内に完了し、
  編集の分かりやすさを5段階中4以上と評価する。（FR-001〜004, FR-007）
- **SC-003**: ネットワークを切断して起動した状態で、本仕様の全受け入れシナリオが成功し、
  認証・通信待ちを理由に利用不能となる操作が0件である。（FR-011）
- **SC-004**: 全20件以上の検証文書を正規形式で取り出して空のローカル環境へ復元し、
  100%で意味的同等性を確認する。形式説明と保存データだけから、文書名、ブロック種別、
  順序、階層、本文、メタデータを100%識別できる。（FR-005〜006, FR-012）
- **SC-005**: 本文・種類・順序・リスト階層の変更を含む100操作を、Undoで開始状態へ、
  Redoで終了状態へ戻せる。新規編集によるRedo無効化と文書間の履歴分離に誤動作がない。
  （FR-010）
- **SC-006**: 計画段階で明記する基準端末上で、1文書1,000ブロック・本文合計10万文字の範囲で、
  20回の計測の95%以上において保存済み文書の表示が2秒以内、見出しへの移動が1秒以内、
  文字入力の画面反映が100ミリ秒以内で完了する。（FR-001, FR-009, FR-015）
- **SC-007**: 保存失敗、読み込み破損、未対応版・種類、識別情報衝突、保存競合の各検証で、
  元データまたは最後の正常保存データの破壊が0件であり、全件で失敗理由が表示される。
  （FR-008, FR-013〜014）
- **SC-008**: 全管理・アウトライン操作の受け入れシナリオで、意図しない別文書の変更、
  誤った見出しへの移動、削除キャンセル時の消失が0件である。（FR-002, FR-009）

## Assumptions

- 初期対象は一人の利用者が使うデスクトップ環境とし、日本語の編集を必須とする。
  アプリの配布形態、技術選定、対応環境の詳細は実装計画で決定する。
- オフライン利用は必要な利用準備を一度完了した後を指す。初回入手までオフラインで
  完結することは求めない。外部アカウントや既存のクラウド基盤への依存はない。
- 見出し6段階、少なくとも3階層の入れ子リスト、100操作の履歴と性能目標は、
  未指定部分に対するMVPの検証基準として設定した前提である。
- リストの本文は基本的なテキストを対象とし、項目内に任意の複雑な文書を埋め込む機能は
  必須としない。コードの言語選択や構文強調も必須ではない。
- Undo／Redoの履歴は文書を閉じる際に破棄してよく、再起動を越える永続化は不要。
  連続した文字入力は利用者に自然な単位でまとめてよいが、構造変更は個別に取り消せる。
- 明示的な保存を必須とし、自動保存は必須としない。正常保存後の保持と失敗時の保護を優先する。
- クラウド同期、リアルタイム共同編集、AIコンテンツ生成、ユーザーアカウント管理、
  高度なドキュメント間リンクは対象外とする。
- 画像、表、高度な装飾、全文検索、外部形式との相互変換、モバイル最適化は必須としない。
  正規形式の取り出し・復元はデータ所有権を満たすため今回の対象に含める。
- AIとの両立の実証は構造と意味を機械的に取得できることで判定し、実AIサービスへの接続や
  AIによる生成品質の評価を要求しない。
