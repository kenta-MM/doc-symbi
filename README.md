# DocSymbi

構造化ドキュメントをローカルで編集するデスクトップ Web アプリです。
段落・見出し・混在入れ子リスト・コード、文書管理、アウトライン、Undo/Redo、
正規 JSON の取り出し／復元、準備後のオフライン起動を実装しています。
PNG・JPEG・WebP・SVGの画像ブロック、キャプション・代替テキスト、AI向けの構成要素／関係／前提／出典データにも対応しています。
実機・利用者評価を含む最終受け入れは未完了です。
進捗と未実施条件は [tasks.md](specs/001-structured-editor-mvp/tasks.md) に記録しています。

## 開発環境

Node.js 22 系（22.12 以上）と npm を使用します。依存関係は lockfile で固定しています。
このワークスペースのローカル Node を使用する場合、PowerShell で次を実行します。

```powershell
$env:PATH = "$PWD\.tools\node-v22.23.4-win-x64;$env:PATH"
$env:PLAYWRIGHT_BROWSERS_PATH = "$PWD\.tools\playwright"
npm ci
npx playwright install chromium
npm run dev
```

## 検証

### VS Code から F5 で起動

このフォルダーを VS Code で開き、F5 を押すと Vite の開発サーバーが起動し、
準備完了後に Chrome で `http://localhost:5173` を開きます。
構成を選ぶ場合は「DocSymbi: F5で起動」を選択してください。
停止はデバッグツールバーでサーバーを選んで Shift+F5。連動するブラウザのデバッグも終了します。
Windows ではこのワークスペースに導入済みの `.tools` 内の Node.js 22 を使用します。
初回に依存がない場合は上記の `npm ci` を先に実行してください。

F5 は変更が即反映される開発用です。オフライン確認は下記の build / preview を使用します。
開発用5173と検証用4173では保存フォルダーの選択をそれぞれ行ってください。同じ記事フォルダーを選べます。

### 自動検証

```powershell
npm run typecheck
npm run lint
npm run test:unit
npm run test:contract
npm run build
npm run test:integration
npm run test:e2e
npm run test:performance
```

build はアプリと Workbox Service Worker を生成し、HTML/JS/CSS/icon/manifest を同梱します。
開発サーバーでは Service Worker を登録しません。オフライン検証には build と preview を使用します。
`npm run preview` は production build を `http://localhost:4173` で表示します。
Playwright はこのポートを専有するため、手動 preview を終了してから実行してください。
自動試験は独立した `.test-build` を生成し、テスト用 harness を含む production-mode preview を使用します。
通常の `dist` には harness を含めません。試験中はこの preview を専有します。
自動試験は通常のブラウザプロファイルを使用せず、persistent profile は OS の一時領域に
`docsymbi-test-*` として作成します。テスト結果、ブラウザ、依存、build は Git 対象外です。

詳細な受け入れ手順は [quickstart.md](specs/001-structured-editor-mvp/quickstart.md) を参照してください。

## 保存と復元

- 最初に「保存フォルダーを選択」で記事の保存先を指定します（デスクトップChrome/Edge）。
  以後はそのフォルダーへ、画像を含む1記事1個の `.docsymbi.json` として保存します。サーバーへ文書を送信しません。
  ファイル名は作成時のタイトルとランダムIDです。タイトル変更後も同じファイルを更新します。
  フォルダー直下のファイルを一覧に表示し、サブフォルダーは探索しません。
- 保存先のハンドルだけをIndexedDB `docsymbi-folder` に記憶します。再起動後にアクセス許可が必要な場合は
  「保存先に再接続」を押します。フォルダーの移動・削除時は保存フォルダーを選び直してください。
- 旧IndexedDB `docsymbi` の記事は「ブラウザ内の記事をコピー」で移せます。元データを保持し、同じIDはスキップします。
  このコピーは現在の origin / ブラウザプロファイルにある保存済み記事が対象です。
- 「保存」または Ctrl+S で明示保存します。未保存の変更は強制終了からの復旧対象ではありません。
- 「文書を取り出す」で現在の編集内容を別の `.docsymbi.json` に出力します。通常の保存とは別のコピーです。
- 「文書を読み込む」で復元します。同じIDが既にある場合は上書きせず拒否します。
  別環境では同じフォルダーを選ぶか、別のフォルダーへ読み込んでください。
- 「オフライン利用の準備完了」が表示された後は、同じ origin / プロファイルでサーバー停止後も利用できます。
  更新版は利用者が適用するまで待機し、未保存時は保存／破棄／キャンセルを確認します。
- 「保存済み」はファイルへの書き込み完了を意味します。保存失敗時は編集内容を保持します。
  外部変更を保存前に検出すると上書きを拒否します。同一originの画面間では書き込みを直列化しますが、
  他アプリや異なるoriginとの厳密な排他はできないため、同じ記事の同時編集は避けてください。
- 不正な形式・重複IDのファイルがある場合はファイル名を表示して操作を止めます。該当ファイルを修正するか別フォルダーへ移してください。
  「文書を削除」は記事ファイルを削除します。必要な記事は事前にコピーしてください。

形式仕様: [document-format.md](docs/document-format.md)。実測と残課題: [validation](specs/001-structured-editor-mvp/validation/acceptance.md)。

## 画像とAI向けデータ

「画像を添付」で選択したブロックの次に画像を挿入します（画像ごと3 MiBまで）。
操作対象で画像を選ぶと、図題・代替テキストと「AI向け構造化データ」を編集できます。
JSONの初期テンプレートに目的、要素と役割、要素間の関係、読み順、前提、出典を記載し、「画像情報を適用」→「保存」で保持します。
情報データはAIが図を解釈するための明示的な記述です。AIへの送信や画像の自動解析は行いません。
画像本体も文書JSONに含まれるため、取り出し／読み込みで復元でき、オフラインでも表示できます。
画像を含む文書はschemaVersion 2となり、旧アプリでは読み込めません。従来のv1文書も引き続き利用できます。

作例: [Hyperscale文書](docs/azure-sql-hyperscale.docsymbi.json) と [SVG・意味データ](docs/hyperscale-figures/)。
`node scripts/create-hyperscale-figures.mjs` で図と意味データを同じ定義から再生成できます。
既に同じ文書を保存している場合は、その文書を開き「現在の文書をファイルで更新」でこのファイルを選びます。
通常の「文書を読み込む」は同じIDの上書きを引き続き拒否します。

## 閲覧と編集

既存記事・読み込んだ記事はビューモード、新規記事は編集モードで開きます。「編集」／「編集を終了」で切り替えます。ビューモードでは本文・文書名を変更できず、編集ツールを非表示にします。目次とコピー、JSONの取り出しは利用できます。モード切り替えは保存操作ではありません。未保存の内容・編集履歴・保存失敗の表示は保持されるため、「保存」で変更を保存してください。

保存先への接続後は前回開いた記事をビューモードで自動表示します。前回の記事が見つからない場合は更新日時が最新の記事を表示します。ブラウザーがフォルダーへのアクセス許可を求める場合は「保存先に再接続」で許可してください。すでに開いている記事や未保存の下書きは再接続で置き換えません。
