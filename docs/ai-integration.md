# ローカルAIチャット（2026-10-30）

前回の「実際にCodex CLIを使ってチャットできるようにする」という依頼の途中実装を引き継ぎ、接続処理・設定表示・検証を整備しました。Claudeは将来用の選択肢で、現在は送信できません。

## 起動とログイン

1. Codex CLIで `codex login` を実行し、`codex login status` でログインを確認します。
2. `npm run dev`、または `npm run build` 後の `npm run preview` で起動します。
3. 右側のAIチャットでCodexを選び「再接続」を押します。接続後はモデルを選び、送信ボタンまたはCtrl / ⌘ + Enterで依頼できます。

WindowsのCodexデスクトップ版が標準位置にある場合、そのCLIを自動検出します。PATHにない場合のログインはPowerShellで次のように実行できます。

```powershell
& "$env:LOCALAPPDATA\Programs\OpenAI\Codex\bin\codex.exe" login
```

それ以外の配置では、サーバー起動前に `DOCSYMBI_CODEX_PATH` にCLI実行ファイルの絶対パスを指定してください。静的ファイル配信だけでは接続できません。

## 動作と範囲

- Codexの既存ログインを利用し、認証情報をブラウザには保存しません。
- 送信時に現在の文書のテキスト・構造・メタデータを共有します。画像ファイル本体は除外します。
- 応答を逐次表示し、会話を継続できます。「停止」で生成を中断し、「新しい会話」で履歴を切り替えます。
- 会話と下書きは文書・AIごとに画面内で保持します。再読み込みで消えます。サーバー再起動後は新しい会話になります。
- 回答はチャットに表示します。本文への自動反映・保存は未実装です。
- オフラインでも下書き操作はできますが、実際のAI応答には接続が必要です。

## 実装

`server/codex-client.ts` はCodex app-serverとのstdio通信、`server/ai-plugin.ts` はViteのローカルAPI、`src/platform/ai-chat.ts` はブラウザ通信、`src/ui/use-ai-chat.ts` は会話の状態を担当します。プロバイダー一覧と選択保存は既存の共通枠を維持しています。

ローカルホスト・同一オリジン・専用ヘッダーを検証し、入力サイズと同時送信を制限します。Codexは一時的な会話を読み取り専用で開始し、シェルとWeb検索を無効にします。対話的なツール承認要求は拒否します。自動テストでは実Codex接続を無効化します。

通信方式は[公式Codex App Server資料](https://learn.chatgpt.com/docs/app-server)とインストール済みCLIが生成するJSON Schemaを確認しました。
