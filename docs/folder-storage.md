# 記事フォルダー保存

2026-10-26: 利用者の指定により、主保存先をIndexedDBから利用者が選ぶフォルダーへ変更。
初期MVPのIndexedDB保存要件に対する追加決定であり、本文・画像の既存JSON形式は変更しない。

- 初回にフォルダーを選び、ハンドルを記憶する。以後、保存/Ctrl+Sは同じ記事ファイルを更新する。
- フォルダー選択の確定と次回用の記憶を分離する。記憶できなくても選んだフォルダーへの保存は継続でき、
  次回の再選択が必要な旨と記憶失敗の詳細を表示する。初回の保存先選択では編集中の記事を保持する。
- 保存先の復元は画面の起動処理だけに依存せず、保存・一覧取得の前にも完了を待つ。
  初期化が再実行されても、既に選択した保存先を未選択状態で上書きしない。
- フォルダー直下に1記事1JSON。タイトルとランダムUUIDでファイル名を作り、以後はJSON内の記事IDで識別する。
- 一覧はファイルから復元する。タイトル変更やアプリ外でのファイル名変更に対応する。
- ファイルの内容ハッシュをrevision比較トークンとし、保存・削除前に外部変更を検査する。
  Web Locksで同一originの書き込みを直列化する。別origin/外部アプリとの検査後の競合は完全には防げない。
- createWritableのclose完了後に保存済みとする。書き込み失敗は未保存内容を保持する。
- 保存先変更には未保存確認を適用する。権限失効時は明示的な再接続操作を求める。
- 旧ブラウザ内の記事は利用者操作でコピーし、元データを削除しない。同じIDはスキップする。
- フォルダー内の不正形式・重複IDはファイル名付きのエラーにし、黙って無視しない。

API根拠: https://developer.chrome.com/docs/capabilities/web-apis/file-system-access

自動E2EはOSピッカーだけをOPFSディレクトリ返却に置換し、実ブラウザのファイル読み書きと
IndexedDBへのハンドル記憶を検証する。ネイティブOSダイアログ、実フォルダーへの権限再確認、
OSのアクセス拒否については実機での手動確認が必要。
